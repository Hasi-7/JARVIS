## Goal

Make the PRD's tool-log/audit spine real (§32) **without enabling any privileged tool**. For v0, log **only Permission Gateway evaluations**:

```text
manual simulated tool request → backend classifies (deny/not_wired/disabled/requires_approval)
→ backend writes one redacted backend-local audit entry → UI shows recent entries → no tool executes
```

Later this extends to real tool calls and vault `ops/tool-logs/`.

### Log storage behavior

Append-only JSON list in backend app-data (never the vault). Latest **500** entries kept (simple slice cap, no rotation). `list_logs` reverses to newest-first, applies exact-match `tool`/`decision` filters, clamps `limit` to [1, 200] (default 50).

### Evaluation ↔ log linkage

`evaluate_tool_request` returns the classification dict (unchanged, pure). The endpoint passes that dict to `log_evaluation()`, which builds the entry from the **already-sanitized** evaluation (so raw args never reach the log path), stores it, and returns it; the endpoint surfaces `entry["id"]` as `logId` on the response.

### Redaction behavior

Only `sanitizedArgsSummary` is stored — there is **no raw-args field**. Secret-bearing keys (`password/token/secret/key/credential/authorization/cookie`) were already redacted upstream and long values truncated; `reason` and `requestedBy` are additionally truncated. `result` is always `evaluated_only`; `allowed`/`executionEnabled` always `false`.

## Safety constraints (this sprint)

- Logs **only** Permission Gateway evaluations — no tool executes; no MCP/Gmail/browser/computer-use/Google/GitHub/Drive call; no OpenClaw/NemoClaw; no shell; no `brain`; no vault write.
- Backend app-data storage only (`backend/data/tool-logs/`); vault `ops/tool-logs/` untouched.
- Raw args and secret values are never persisted; only the sanitized summary is stored.
- No clear/delete/replay log actions exist (UI or API).
